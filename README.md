# OSArch Wiki

The OSArch Wiki is a community-maintained, Git-backed knowledge base built with
[Hugo](https://gohugo.io/). It is a static site.

The published site is <https://wiki.osarch.org/> and its repository is
<https://github.com/osarchorg/wiki>.

## Editing the wiki

Articles live in `content/wiki/` as Markdown files. You can edit a file directly
on GitHub using the **Edit this page** link, or clone the repository for larger
changes. Each article begins with front matter:

```yaml
---
title: "Example article"
url: "/example-article/"
aliases: ["/Old_MediaWiki_title/"]
categories: ["Documentation"]
parent: "/parent-article/"
---
```

- Keep `url` stable after publication. If it must change, add the previous URL
  to `aliases` so existing links continue to work.
- Categories are ordinary strings. Reuse a spelling already shown on the
  `/categories/` page rather than creating a near-duplicate.
- For a subpage, set `parent` to its immediate parent's canonical `url`. A
  parent page can render its direct children with `{{</* subpages */>}}`.
  Subpage relationships are independent of filenames and URL nesting.
- Put uploaded files in `static/media/` and reference them as `/media/name.png`.
- Featured links in the left navigation are selected in
  `data/featured_pages.yaml`.
- Shortcodes in `layouts/shortcodes/` provide the migrated image and video
  presentation. Normal Markdown is preferred for new content where possible.

All contributions are tracked through Git commits and pull requests. The page
history link opens the relevant GitHub commit history.

## Local preview

Install Hugo Extended 0.147.7 or newer, then run:

```sh
hugo server
```

The preview is normally available at <http://localhost:1313/>. This is enough
for writing and layout work, but the search index is only generated by the full
build.

## Full build and search

Pagefind is distributed as a standalone binary and is pinned by the installer.

```sh
scripts/install_pagefind.sh   # once per machine
scripts/build.sh
```

The complete site is written to `public/`. Serve that directory when testing
search:

```sh
python3 -m http.server --directory public 8000
```

Then open <http://localhost:8000/>.

## Recently updated and page dates

The full build runs `scripts/update_lastmod.py`, which writes the date of each
article's latest Git commit into its `lastmod` front matter. The date shown on
an article is therefore the date of the most recent commit that changed that
file. The home page sorts `site.RegularPages.ByLastmod.Reverse`, so **Recently
updated** requires no database or scheduled task.

The build must have full Git history. The deployment workflow therefore checks
out with `fetch-depth: 0`. A shallow checkout can give incomplete dates. Before
the repository has its first commit, the updater safely retains the imported
`lastmod` values. An article with only the initial import commit also retains
its MediaWiki date. Git becomes authoritative after a later commit changes that
article, so the list becomes naturally useful as pages receive subsequent edits.
`hugo server` does not run the updater, so run `scripts/build.sh` when you need
to verify dates and the final Recent changes ordering.

## Image and video policy

Published raster images must fit inside an 800×800 pixel bounding box. Images
are never enlarged.

- Use PNG for diagrams, interface captures, transparency, and line artwork.
- Use JPEG for photographs; the optimiser caps quality at 85, strips metadata,
  and writes progressive JPEGs.
- SVG is preferred for suitable vector artwork and is not rasterised.
- Do not commit GIFs. Static GIFs should become PNG. Animation and screen
  recordings should become H.264 MP4 with a PNG poster and use the
  `wiki-video` shortcode.

After adding or replacing raster images, run:

```sh
python3 scripts/optimise_images.py static/media
```

This constrains images to 800px, runs `pngcrush` and `optipng` on PNGs, and
`jpegoptim` on JPEGs. It requires ImageMagick, pngcrush, optipng, and jpegoptim.
Review and commit the resulting files. The migration originals are deliberately
not part of this repository.

Example video markup:

```text
{{</* wiki-video src="/media/example.mp4" poster="/media/example.png" title="Example workflow" */>}}
```

## Legacy MediaWiki URLs

Each migrated article carries Hugo `aliases` for its former MediaWiki paths and
redirect titles. Hugo generates static redirect pages for those aliases. The
custom 404 page also recognises legacy `/index.php?title=Article_Name` links and
redirects them in the browser.

GitHub Pages cannot issue server-side redirects based on query strings, so that
fallback initially returns a 404 response before JavaScript redirects. If the
domain is later placed behind Cloudflare or another edge proxy, configure a
permanent redirect from `/index.php?title=...` to the canonical wiki URL for
better crawler semantics. Do not remove article aliases when doing so.

## Deployment

`.github/workflows/deploy.yml` builds and publishes the site through GitHub
Pages whenever `master` is updated. It installs the pinned Hugo and Pagefind
versions, builds with full Git history, and uploads `public/` as the Pages
artifact. `static/CNAME` declares `wiki.osarch.org` as the custom domain.

To publish a new version, merge or push to `master` and watch the **Build and
deploy wiki** action. No generated `public/` files should be committed.
